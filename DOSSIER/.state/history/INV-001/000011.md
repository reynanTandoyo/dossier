## Problem

take and return from a PC fail for a server path with spaces or wildcard characters

Observed: scp reported No such file or directory for /srv/my project/sim/run 1.sim when the path was quoted for a shell

## Attempts

1. [failed] Quote the remote path for a shell, as the ssh commands are quoted — did: scp server:'/srv/my project/sim/run 1.sim' — result: No such file or directory: in SFTP mode the quotes became part of the name — task: T-405 (2026-11-25T07:34:44+01:00 reyna via reyna - claude)
2. [failed] Use the legacy scp protocol, which reads the path through a shell — did: scp -O with the quoted path, then with the unquoted path — result: Protocol error: filename does not match request; unquoted, the name was cut at the space — task: T-405 (2026-11-25T07:34:44+01:00 reyna via reyna - claude)
3. [worked] Pass the path unquoted in SFTP mode — did: scp -s server:/srv/my project/sim/run 1.sim, and an upload the other way — result: Download and upload work, also with a space and a quote in the name — task: T-405 (2026-11-25T07:34:44+01:00 reyna via reyna - claude)
4. [failed] Leave wildcard characters as they are — did: scp -s server:/srv/p/a*b.sim — result: Also copied axxb.sim: SFTP globs the source path — task: T-405 (2026-11-25T07:34:44+01:00 reyna via reyna - claude)
5. [worked] Put a backslash before each of \ * ? [ ] in the source path — result: Only a*b.sim was copied — task: T-405 (2026-11-25T07:34:44+01:00 reyna via reyna - claude)
6. [failed] Escape the upload target in the same way — did: scp -s up.sim "server:/srv/p/up \[1\]\*.sim" — result: The backslashes became part of the name on the server: SFTP does not glob a target — task: T-373 (2026-11-25T07:34:44+01:00 reyna via reyna - claude)

## Solution

scp -s with an unquoted path; wildcard characters are escaped in a download source (remote_path) only, and an upload target (remote_target) is passed as typed

Attempts: 3, 5
